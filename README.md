# Retro2D

Retro2D is a small C11 framework for 320 x 200-style indexed-colour games. It
owns the fixed-step loop and uses SDL3 behind a plain C API for the window,
input, presentation, timing, and audio device. Game code includes only
`retro2d.h`; it never needs SDL types.

The core is intentionally genre-neutral. It provides a byte-per-pixel virtual
screen, drawing, BMP sprites, bitmap text, input edges, PCM WAVE playback,
animation, collision helpers, and ordered software effects. It does not impose
entities, scenes, physics, maps, or a particular game structure.

See [`manual.md`](manual.md) for the complete feature and function reference
with short code examples.

## Prerequisites and Windows build

Install:

- Visual Studio 2026 with **Desktop development with C++** (the framework is C,
  but this workload supplies MSVC and the Windows SDK).
- CMake 4.2 or newer, which provides the Visual Studio 2026 generator. Download
  the current Windows x64 installer from the
  [official CMake site](https://cmake.org/download/) if `cmake --version` reports
  an older release. During installation, add CMake to the system `PATH`.
- Git is useful but is not required when CMake downloads SDL3 from its release
  archive.

Check the tools from a **Developer PowerShell for VS 2026**:

```powershell
cmake --version
cmake --help | Select-String "Visual Studio 18"
```

The second command should list `Visual Studio 18 2026`. From the repository
root, configure, compile, and test the Release build:

```powershell
cmake -S . -B build-vs2026 -G "Visual Studio 18 2026" -A x64
cmake --build build-vs2026 --config Release
ctest --test-dir build-vs2026 -C Release --output-on-failure
```

The configure command consists of:

- `cmake`: runs CMake's configure/generate mode.
- `-S .`: uses the current directory (`.`) as the source tree containing
  `CMakeLists.txt`.
- `-B build-vs2026`: writes generated projects, downloaded dependencies, object
  files, and executables into a separate `build-vs2026` directory.
- `-G "Visual Studio 18 2026"`: requests project files for the installed Visual
  Studio 2026 instance. Visual Studio 2022 instead uses
  `"Visual Studio 17 2022"`.
- `-A x64`: selects 64-bit Windows as the target architecture.

The build command consists of:

- `cmake --build`: asks CMake to invoke the native build tool selected during
  configuration; for this generator, that is MSBuild.
- `build-vs2026`: selects the already-configured build tree.
- `--config Release`: chooses the optimized Release configuration. Use
  `--config Debug` when debugging.

The test command consists of:

- `ctest`: runs tests registered by the CMake project.
- `--test-dir build-vs2026`: finds the tests in that build tree.
- `-C Release`: tests the Release configuration generated by Visual Studio.
- `--output-on-failure`: keeps successful output compact but prints diagnostics
  for a failed test.

Use a new build directory when changing generators. CMake records the generator
in its cache, so an existing Visual Studio 2022 build directory cannot be
reconfigured in place as a Visual Studio 2026 build directory.

CMake first looks for an installed SDL3 package. If it cannot find one, the
default `RETRO2D_FETCH_SDL3=ON` downloads the pinned SDL3 source release and
builds its shared library. For an offline build, install SDL3, pass its package
directory through `-DSDL3_DIR=...`, and configure with
`-DRETRO2D_FETCH_SDL3=OFF`.

The executables are normally under `build-vs2026/Release` (single-configuration
generators put them directly under their build directory). The build copies
`SDL3.dll` and generates the original placeholder assets beside every example
automatically.

Run:

```powershell
.\build-vs2026\Release\sprite_demo.exe
.\build-vs2026\Release\point_click.exe
.\build-vs2026\Release\effects_demo.exe
.\build-vs2026\Release\fullscreen_pong.exe
```

- `sprite_demo`: arrows move, Space fires, Escape exits.
- `point_click`: click the window or door, M pauses/resumes music.
- `effects_demo`: Up/Down fades the palette, Space toggles water displacement.
- `fullscreen_pong`: 640 x 480 borderless fullscreen Pong; W/S or arrows move,
  Space serves, P pauses, and Escape exits. A controller's left stick and A
  button are also supported.

## A complete minimal game

```c
#include "retro2d.h"

static int player_x = 152;

void game_start(void)
{
    set_palette_colour(0, (Color){ 0, 0, 0, 255 });
    set_palette_colour(1, (Color){ 255, 255, 255, 255 });
}

void game_update(float delta)
{
    if (key_down(KEY_LEFT))  player_x -= (int)(100 * delta);
    if (key_down(KEY_RIGHT)) player_x += (int)(100 * delta);
    if (key_pressed(KEY_ESCAPE)) request_quit();
}

void game_draw(void)
{
    clear_screen(0);
    fill_rectangle((Rect){ player_x, 92, 16, 16 }, 1);
}

void game_stop(void) {}

int main(void)
{
    GameConfig config = {
        .title = "My Game",
        .screen_width = 320,
        .screen_height = 200,
        .window_scale = 3,
        .update_rate = 60,
        .vertical_sync = true
    };
    return run_game(&config);
}
```

The framework calls `game_update` at a fixed rate and passes seconds as
`delta`. Rendering may occur independently. A long debugger pause is clamped,
and catch-up work is bounded so the game does not spiral indefinitely.

## The indexed screen

The virtual framebuffer is one byte per pixel. A byte is an index into the
active array of 256 RGBA palette colours; changing a palette entry changes every
presented pixel using that index without redrawing objects. The default palette
is a 6 x 6 x 6 RGB cube followed by 40 greys.

`get_framebuffer()` returns the framework-owned pixel pointer, dimensions, and
stride. Direct access is valid only from the four game callbacks. Do not free or
retain the pointer beyond a callback. Normal drawing clips at screen and clip
stack boundaries. `set_camera(x, y)` subtracts a world-space camera position
from later drawing.

The window uses nearest-neighbour sampling and the largest scale that preserves
the virtual aspect ratio. Exact multiples remain integer-scaled; otherwise a
fractional scale fills as much of the window or fullscreen display as possible.
Unused space is cleared to black. `mouse_position()` reports virtual
coordinates; it returns `(-1, -1)` over a border, where
`mouse_inside_screen()` is false.

Palette operations include individual and whole-palette access, RGB/RGBA `.pal`
files, range rotation, and calculated fades. Preserve an original palette and
call `make_faded_palette` each update for a stable time-based fade; repeatedly
fading the already-faded active palette compounds the result.

## BMP images and transparency

`load_image` accepts uncompressed 8-bit indexed and common 24/32-bit BMP files.
Indexed pixel values are preserved, so exact artwork should use the game's
palette. True-colour pixels are mapped to the nearest active palette colour at
load time and may lose colour detail. Load true-colour art after establishing
the final palette.

```c
Image *hero = load_image("assets/hero.bmp");
image_set_colour_key(hero, 0);
draw_image(hero, 40, 60);
draw_image_part(hero, (Rect){ 16, 0, 16, 16 }, 80, 60, FLIP_HORIZONTAL);
free_image(hero);
```

A colour key skips every source pixel with that palette index. An explicit mask
uses one bit per pixel, most-significant bit first in each byte; set bits draw
and clear bits are transparent. For a 32-bit BMP containing meaningful alpha,
the loader creates the same 1-bit mask. `set_image_alpha_threshold(128)` changes
the cutoff for images loaded afterward. If every alpha byte is zero, the loader
treats the high byte as unused and the image as opaque, which handles common
XRGB BMP files.

Sprite sheets divide an image into equal cells. A `SpriteSheet` is shared;
`Animation` owns only playback state and a frame list, so many objects can use
one image at different animation times. Free animations before their sheet and
free the sheet before its image.

## Bitmap text

A font is a row-major glyph sheet with equal-sized cells. This defines ASCII 32
through 127 in 16 columns:

```c
BitmapFont *font = load_bitmap_font("assets/font.bmp", 8, 8, 32, 96, 16);
font_set_colour_key(font, 0);
font_set_spacing(font, 1, 2);
draw_text(font, "HELLO\nRETRO WORLD", 160, 20, ALIGN_CENTRE);
Point size = measure_text(font, "HELLO");
```

Multiline strings are aligned line by line. A font loaded from a path owns its
image; `free_bitmap_font` releases both. A font made with
`create_bitmap_font` borrows the supplied image.

## Keyboard, mouse, and controller input

Held, pressed, and released are distinct:

- `key_down(KEY_SPACE)` stays true for every update while held.
- `key_pressed(KEY_SPACE)` is true for only the first fixed update after a
  press.
- `key_released(KEY_SPACE)` is true for only the first update after release.

Mouse and controller buttons follow the same rule. Mouse movement and wheel
values accumulate between updates and reset after they are delivered. Basic
first-controller buttons, sticks, and triggers are exposed without SDL enums.
Cursor visibility and confinement are optional window controls.

## Sound and music

The baseline loader accepts uncompressed PCM WAVE with 8-bit or 16-bit samples,
mono or stereo. It converts once at load time to 44.1 kHz stereo. Up to 32 sound
voices mix by default (configure up to 64); music has a separate voice and
volume.

```c
Sound *laser = load_sound("assets/laser.wav");
Playback shot = play_sound(laser);       /* The handle may be ignored. */
set_playback_pan(shot, -0.5f);

Music *theme = load_music("assets/theme.wav");
fade_music_in(theme, true, 1.0f);
fade_music_out(0.5f);

free_sound(laser);
free_music(theme);
```

Sound resources must remain alive while playing. Freeing one stops its active
instances safely. When no audio device is available, loading still works and
play calls become harmless no-ops after a warning.

## Software post-processing

Effects run in registration order. Source and destination are always different,
and the destination starts as a copy of the source. Two full-screen scratch
buffers are allocated once at startup and reused; no full-screen allocation
occurs per frame. With no active effects, presentation uses the framebuffer
directly.

```c
static void water(const uint8_t *src, uint8_t *dst,
                  int width, int height, int src_stride, int dst_stride,
                  const Color *palette, float elapsed, void *user_data)
{
    int phase = (int)(elapsed * 20);
    (void)palette; (void)user_data;
    for (int y = height / 2; y < height; ++y) {
        int offset = ((y + phase) & 7) - 3;
        for (int x = 0; x < width; ++x) {
            int sample = x + offset;
            if (sample < 0) sample = 0;
            if (sample >= width) sample = width - 1;
            dst[y * dst_stride + x] = src[y * src_stride + sample];
        }
    }
}

EffectHandle effect = add_effect(water, NULL);
enable_effect(effect, false);
move_effect(effect, 0);
remove_effect(effect);
```

Use palette changes instead of a framebuffer effect for fades, flashes, and
colour cycling; palette-only changes avoid a screen copy.

## Compact API map

- Lifecycle: `run_game`, `request_quit`, `elapsed_time`, frame/update counters,
  FPS and timing queries.
- Screen: framebuffer access, clear, palette set/get/load/save/rotate/fade.
- Drawing: pixels, lines, rectangles, circles, camera, nested clip stack.
- Images: BMP load/create/free, colour key, mask, regions, flips.
- Sprites: sheet creation, source lookup, frame draw, range/explicit animation,
  play/pause/reset/loop/speed/finished.
- Text: font load/define/free, spacing, measure, multiline aligned drawing.
- Input: keyboard, mouse, cursor, and first-controller states.
- Audio: WAVE sound/music load/free, simultaneous playback, handles, volume,
  pan, pause/resume/stop, loop, fades.
- Effects: add/remove/enable/reorder an ordered callback chain.
- Collision: point/rectangle, rectangle/rectangle, circle/circle, and image masks.
- Diagnostics: readable `last_error`, log levels, and a custom log callback.

The declarations and exact parameter types are in
[`include/retro2d.h`](include/retro2d.h).

## Errors, ownership, and cleanup

Loaders return `NULL` and set `last_error()` on failure; no missing asset is
silently substituted. Explicit `free_*` functions are preferred. Framework
shutdown also releases any remaining tracked resources. Complex structs are
opaque, common operations allocate their own buffers, and sprite drawing does
not allocate.

Debug builds keep normal C assertions available. Framework diagnostics use
informational, warning, and error levels through `log_message`; install a
callback with `set_log_callback` to route them into a game console or file.

## Packaging for another Windows PC

For a distributable game, create a clean folder containing:

1. The Release game executable, for example `sprite_demo.exe`.
2. `SDL3.dll` from the same `build-vs2026/Release` directory.
3. The `assets` directory, preserving exactly the relative paths used by the
   game, such as `assets/font.bmp`.
4. Your licence/readme and an SDL third-party licence notice. These are not
   loaded at runtime, but should travel with a public distribution.

Retro2D is a static library, so there is no separate `retro2d.dll` to package.
For the supplied examples, the smallest asset sets are:

| Executable | Required assets |
|---|---|
| `sprite_demo.exe` | `assets/sprites.bmp`, `assets/font.bmp`, `assets/laser.wav` |
| `point_click.exe` | `assets/room.bmp`, `assets/font.bmp`, `assets/music.wav` |
| `effects_demo.exe` | `assets/water.bmp`, `assets/font.bmp` |
| `fullscreen_pong.exe` | `assets/font.bmp`, `assets/laser.wav` |

The complete example build generates one shared `assets` directory containing
all six files. It is safe and simplest to copy that entire directory. Files such
as `.lib`, `.obj`, `.exp`, CMake files, generated Visual Studio projects, and the
test executable are build-time files and are not required by the game. A `.pdb`
is optional: include it separately when you want useful crash-debugging symbols,
but it is not needed to run the game.

The target computer does not need CMake, Visual Studio, SDL development files,
or DOSBox. Build the same architecture as the destination (the documented
configuration is x64). If the MSVC runtime is not already present, install the
current [Microsoft Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
or choose the corresponding deployment option for your organisation.

## Tests and current limits

`retro2d_tests` covers all four drawing edges and clipping, palette operations,
colour-key and bitmask transparency, sprite frame calculations, keyboard and
mouse transitions, letterbox mouse mapping, collision, effect-buffer chaining,
and readable resource-load failure.

Deliberately deferred optional features are PNG/JPEG, OGG/MP3, partial indexed
alpha blending, arbitrary sprite rotation/scaling, TrueType fonts, and GPU
shader hooks. They are not required by the BMP/PCM baseline and would add format
or renderer dependencies. Resource path caching is also deferred to keep
ownership explicit. SDL-specific and decoder-specific work remains isolated so
these conveniences can be added without changing ordinary game code.
